# Диалог тестовой версии

Приложение отправляет новое сообщение и до шести реплик текущего онлайн-диалога методом `POST /v1/chat`. Ответ имеет вид `{"reply":"…"}`. Хост указан в `CloudConversation.origin`. Для доступа с iPhone нужны заголовки `Content-Type: application/json`, `Accept: application/json` и `Origin` с адресом сервиса. Архив и файлы остаются на устройстве.

Сервер запускается как Worker ES module с точкой входа `worker.mjs`, привязкой D1 `DB` и серверным секретом `OPENAI_API_KEY`. Миграция `schema.sql` создаёт таблицу резервирования запросов. Для новой базы Worker также создаёт эту таблицу при первом запросе. В таблице сохраняются день и псевдоним источника запроса, который меняется ежедневно. Текст сообщений в таблицу не записывается.

Пилот допускает 12 попыток в сутки с одного сетевого адреса, 60 попыток в сутки для всего сервиса и 250 попыток за весь пилот. Границы суток заданы по UTC. Резервирование происходит до вызова OpenAI, поэтому попытка с ошибкой тоже расходует квоту. Устройства за одним адресом делят дневной лимит. Внешний вызов ограничен 20 секундами и 300 токенами ответа.

Тесты бюджета и контракта запускаются командой `node --test server/chat/worker.test.mjs` на Node 24. Проверка `Live pilot chat` в GitHub Actions отправляет одно синтетическое приветствие на опубликованный сервер. Проверка `GET /health` подтверждает лишь доступность Worker. Полный путь подтверждает ответ HTTP 200 с непустым полем `reply` на приветствие. Для диагностики ошибок провайдера используйте журналы серверной версии, которая пишет только HTTP-статус и известный код ошибки, и раздел Usage проекта OpenAI.

### Расшифровка голосовой записи

`POST /v1/transcribe` принимает байты файла M4A в теле запроса с `Content-Type: audio/mp4`. Приложение записывает до 120 секунд монофонического AAC. Сервер проверяет размер (до 2 МиБ), звуковую дорожку и длительность (до 125 секунд с запасом на кадры кодека). Затем он отправляет запись в OpenAI на `/v1/audio/transcriptions` с моделью `gpt-transcribe`. Успешный ответ имеет вид `{"text":"…"}`. Пустая расшифровка и результат длиннее 4000 символов возвращают HTTP 422. Внешний запрос ограничен 45 секундами.

Для расшифровки действуют собственные квоты в 12, 60 и 250 попыток по тем же правилам, что для диалога. Worker при первом голосовом запросе создаёт таблицу `pilot_transcription_reservations` в существующей D1. Она хранит только дату и ежедневный псевдоним источника. Worker обрабатывает аудио и расшифровку в памяти и исключает их из своих журналов. Отправленное голосовое сообщение расходует одну попытку расшифровки, а последующий запрос ответа собеседника — одну попытку диалога.
